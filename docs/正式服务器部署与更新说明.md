# 正式服务器部署与更新说明

## 1. 当前正式环境

| 项目 | 内容 |
| --- | --- |
| 公网 IP | `43.142.125.17` |
| SSH 用户 | `ubuntu` |
| 域名 | `https://biaoji.aleo1314.vip/` |
| 管理后台 | `https://biaoji.aleo1314.vip/` |
| 查询页面 | `https://biaoji.aleo1314.vip/query/` |
| 健康检查 | `https://biaoji.aleo1314.vip/health` |
| SSH 登录 | 本机已配置 Ed25519 密钥免密登录 |

本次正式环境由测试服务器 `212.64.16.212` 迁移而来。迁移的是数据库快照、后端 JAR、两个前端、上传文件、文件数据和服务器运行配置。测试服务器后续新增的数据不会自动同步到正式服务器。

不要把 `/etc/query/query.env` 下载到项目、提交 Git 或写入文档。该文件包含数据库密码和应用密钥。

## 2. 部署结构

```text
HTTPS :443 -> Nginx
    |-- /              -> /var/www/query/admin
    |-- /query/        -> Python 127.0.0.1:18765
    |-- /prod-api/     -> Java 127.0.0.1:8080
    `-- /health        -> Python 健康检查

Java -> MariaDB 127.0.0.1:3306 / verifynum
```

重要目录：

- `/opt/query/geek-admin.jar`：Java 后端
- `/opt/query/free-query`：免费查询服务
- `/var/www/query/admin`：管理端构建产物
- `/var/lib/query/uploads`、`/var/lib/query/files`：业务文件数据
- `/etc/query/query.env`：正式环境变量和密钥，仅服务器保存
- `/etc/nginx/sites-available/query`：Nginx 配置
- `/var/backups/query`：数据库和程序备份

## 3. 每次更新前检查和备份

在本机项目根目录执行：

```powershell
$stamp = Get-Date -Format 'yyyyMMdd_HHmmss'
ssh ubuntu@43.142.125.17 "systemctl is-active query-backend query-free nginx mariadb"
ssh ubuntu@43.142.125.17 "sudo mariadb-dump --single-transaction --routines --triggers verifynum | gzip | sudo tee /var/backups/query/verifynum-before-update-$stamp.sql.gz > /dev/null"
```

重要更新再备份当前程序。备份目录使用时间戳，不要先删除旧备份：

```powershell
ssh ubuntu@43.142.125.17 "sudo mkdir -p /var/backups/query/program-$stamp; sudo cp /opt/query/geek-admin.jar /var/backups/query/program-$stamp/; sudo cp -a /opt/query/free-query /var/backups/query/program-$stamp/; sudo cp -a /var/www/query/admin /var/backups/query/program-$stamp/; sudo cp -a /etc/nginx/sites-available/query /var/backups/query/program-$stamp/query.nginx"
```

## 4. 更新 Java 后端

本地构建（正式服务器使用 Java 21）：

```powershell
cd backend
mvn clean package -DskipTests
cd ..
scp backend\geek-admin\target\geek-admin.jar ubuntu@43.142.125.17:/tmp/geek-admin.jar.new
```

上传完成后，在本机执行切换。先停止服务，再安装新 JAR；旧版本已在更新前备份：

```powershell
ssh ubuntu@43.142.125.17 "sudo systemctl stop query-backend; sudo install -o queryapp -g queryapp -m 0640 /tmp/geek-admin.jar.new /opt/query/geek-admin.jar; rm -f /tmp/geek-admin.jar.new; sudo systemctl start query-backend"
```

## 5. 更新管理端前端

管理端部署在根路径 `/`，构建时必须使用 `/` 基础路径：

```powershell
cd frontend\ruoyi-geek-vue3
$env:VITE_BASE_ROUTER = '/'
npm.cmd ci
npm.cmd run build:prod
cd ..\..
```

上传到临时目录，确认上传完成后再切换：

```powershell
ssh ubuntu@43.142.125.17 "rm -rf /tmp/query-admin.new"
scp -r frontend\ruoyi-geek-vue3\dist ubuntu@43.142.125.17:/tmp/query-admin.new
ssh ubuntu@43.142.125.17 "sudo mv /var/www/query/admin /var/www/query/admin.previous-$stamp; sudo mv /tmp/query-admin.new /var/www/query/admin; sudo chown -R root:root /var/www/query/admin; sudo find /var/www/query/admin -type d -exec chmod 755 {} +; sudo find /var/www/query/admin -type f -exec chmod 644 {} +"
```

静态文件更新通常不需要重启 Nginx。

## 6. 更新免费查询页面

```powershell

```

## 7. 数据库变更

日常更新禁止导入 `backend/sql/verifynum.sql`，该文件含有删表和初始化数据，会覆盖正式数据。

新增表或字段时，写只包含本次变更的增量 SQL。先备份，再上传和执行：

```powershell
$stamp = Get-Date -Format 'yyyyMMdd_HHmmss'
ssh ubuntu@43.142.125.17 "sudo mariadb-dump --single-transaction --routines --triggers verifynum | gzip | sudo tee /var/backups/query/verifynum-before-sql-$stamp.sql.gz > /dev/null"
scp backend\sql\本次增量.sql ubuntu@43.142.125.17:/tmp/query-update.sql
ssh ubuntu@43.142.125.17 "sudo mariadb verifynum < /tmp/query-update.sql; rm -f /tmp/query-update.sql; sudo systemctl restart query-backend"
```

执行后检查表结构和关键数据。除非明确确认需要恢复，否则不要导入全量备份；恢复会覆盖备份时间点之后的数据。

## 8. 修改正式环境配置

配置只在正式服务器修改：

```powershell
ssh ubuntu@43.142.125.17 "sudoedit /etc/query/query.env"
```

修改后按影响范围重启：

```powershell
ssh ubuntu@43.142.125.17 "sudo systemctl restart query-backend query-free"
```

不要用测试服务器的 `query.env` 覆盖正式配置。修改 Nginx 后必须先检查再重载：

```powershell
ssh ubuntu@43.142.125.17 "sudo nginx -t && sudo systemctl reload nginx"
```

```powershell
ssh ubuntu@43.142.125.17 "systemctl is-active query-backend query-free nginx mariadb"
curl.exe -fsS https://biaoji.aleo1314.vip/health
curl.exe -fsS https://biaoji.aleo1314.vip/h5/mark/policy
curl.exe -fsSI https://biaoji.aleo1314.vip/ | Select-Object -First 8
curl.exe -fsSI https://biaoji.aleo1314.vip/query/ | Select-Object -First 8
ssh ubuntu@43.142.125.17 "sudo ss -lntp | grep -E ':(80|443|3306|8080|18765) '"
ssh ubuntu@43.142.125.17 "sudo journalctl -u query-backend -u query-free -n 100 --no-pager"
```

正常状态：四个服务均为 `active`；HTTPS 页面返回 `200`；`/health` 返回 `status: ok`；3306、8080、18765 仅监听 `127.0.0.1`。

## 10. 回滚

Java 回滚示例：

```powershell
ssh ubuntu@43.142.125.17 "sudo systemctl stop query-backend; sudo cp /var/backups/query/program-时间戳/geek-admin.jar /opt/query/geek-admin.jar; sudo chown queryapp:queryapp /opt/query/geek-admin.jar; sudo systemctl start query-backend"
```

管理端和免费查询页回滚时，将当前目录改名为 `.failed-时间戳`，再把对应备份目录移回原路径。数据库只在确认增量 SQL 无法修复时，使用对应时间点的备份恢复。

## 11. HTTPS 证书

证书由 Certbot 自动续期。检查证书和续期模拟：

```powershell
ssh ubuntu@43.142.125.17 "sudo certbot certificates"
ssh ubuntu@43.142.125.17 "sudo certbot renew --dry-run"
```

域名必须继续解析到 `43.142.125.17`，并确保公网 80、443 端口可访问。

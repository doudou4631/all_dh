## 2. 部署结构

```text
HTTPS :443 -> Nginx
    |-- /              -> /var/www/query/admin
    |-- /query/        -> Python 127.0.0.1:18765
    |-- /prod-api/     -> Java 127.0.0.1:8080
    `-- /health        -> Python 健康检查

Java -> Node TDX `query-tdx` 127.0.0.1:4320
Java -> MariaDB 127.0.0.1:3306 / verifynum
```

当前正式环境的 Node TDX 服务与 Java 后端部署在同一台服务器，不使用另一台 TDX 主机。`query-backend` 通过 `TDX_SECOND_BASE_URL=http://127.0.0.1:4320` 调用它；只有独立迁移方案才会把 Node 服务放到其他服务器。

当前线路角色：线路1为主用线路，线路2为备用线路（外部 API），线路3已启用失败订单复用。

重要目录：

- `/opt/query/geek-admin.jar`：Java 后端
- `/opt/query/tdx-executor`：Node TDX 二次申诉服务
- `/opt/query/free-query`：免费查询服务
- `/var/www/query/admin`：管理端构建产物
- `/var/lib/query/uploads`、`/var/lib/query/files`：业务文件数据
- `/etc/query/query.env`：正式环境变量和密钥，仅服务器保存
- `/etc/query/tdx.env`：Node TDX 服务环境变量，仅服务器保存
- `/etc/nginx/sites-available/query`：Nginx 配置
- `/var/backups/query`：数据库和程序备份

## 3. 每次更新前检查和备份

在本机项目根目录执行：

```powershell
$stamp = Get-Date -Format 'yyyyMMdd_HHmmss'
ssh ubuntu@43.142.125.17 "systemctl is-active query-backend query-tdx query-free nginx mariadb"
ssh ubuntu@43.142.125.17 "sudo mariadb-dump --single-transaction --routines --triggers verifynum | gzip | sudo tee /var/backups/query/verifynum-before-update-$stamp.sql.gz > /dev/null"
```

重要更新再备份当前程序。备份目录使用时间戳，不要先删除旧备份：

```powershell
ssh ubuntu@43.142.125.17 "sudo mkdir -p /var/backups/query/program-$stamp; sudo cp /opt/query/geek-admin.jar /var/backups/query/program-$stamp/; sudo cp -a /opt/query/tdx-executor /var/backups/query/program-$stamp/; sudo cp -a /opt/query/free-query /var/backups/query/program-$stamp/; sudo cp -a /var/www/query/admin /var/backups/query/program-$stamp/; sudo cp -a /etc/query/query.env /var/backups/query/program-$stamp/query.env; sudo cp -a /etc/query/tdx.env /var/backups/query/program-$stamp/tdx.env; sudo cp -a /etc/nginx/sites-available/query /var/backups/query/program-$stamp/query.nginx"
```

## 4. 更新 Java 后端

本地构建（正式服务器使用 Java 21）：

```powershell
cd backend
mvn clean package -DskipTests
cd ..
scp backend\geek-admin\target\geek-admin.jar ubuntu@43.142.125.17:/tmp/geek-admin.jar.new
```

上传完成后，在本机执行切换。先停止服务，再安装新 JAR；旧版本已在更新前备份：

```powershell
ssh ubuntu@43.142.125.17 "sudo systemctl stop query-backend; sudo install -o queryapp -g queryapp -m 0640 /tmp/geek-admin.jar.new /opt/query/geek-admin.jar; rm -f /tmp/geek-admin.jar.new; sudo systemctl start query-backend"
```

## 7. 数据库变更

日常更新禁止导入 `backend/sql/verifynum.sql`，该文件含有删表和初始化数据，会覆盖正式数据。

新增表或字段时，写只包含本次变更的增量 SQL。先备份，再上传和执行：

```powershell
$stamp = Get-Date -Format 'yyyyMMdd_HHmmss'
ssh ubuntu@43.142.125.17 "sudo mariadb-dump --single-transaction --routines --triggers verifynum | gzip | sudo tee /var/backups/query/verifynum-before-sql-$stamp.sql.gz > /dev/null"
scp backend\sql\本次增量.sql ubuntu@43.142.125.17:/tmp/query-update.sql
ssh ubuntu@43.142.125.17 "sudo mariadb verifynum < /tmp/query-update.sql; rm -f /tmp/query-update.sql; sudo systemctl restart query-backend"
```

执行后检查表结构和关键数据。除非明确确认需要恢复，否则不要导入全量备份；恢复会覆盖备份时间点之后的数据。

## 8. 修改正式环境配置

配置只在正式服务器修改：

```powershell
ssh ubuntu@43.142.125.17 "sudoedit /etc/query/query.env"
```

Node TDX 服务使用单独的环境文件：

```powershell
ssh ubuntu@43.142.125.17 "sudoedit /etc/query/tdx.env"
```

例如线路1和线路3维护开关分别由 `TDX_LINE1_MAINTENANCE=0`、`TDX_LINE3_MAINTENANCE=0` 控制。线路2作为备用线路保留，不要把这两个环境文件下载到项目或提交 Git。

修改后按影响范围重启：

```powershell
ssh ubuntu@43.142.125.17 "sudo systemctl restart query-backend query-free"
ssh ubuntu@43.142.125.17 "sudo systemctl restart query-tdx"
```

不要用测试服务器的 `query.env` 覆盖正式配置。修改 Nginx 后必须先检查再重载：

```powershell
ssh ubuntu@43.142.125.17 "sudo nginx -t && sudo systemctl reload nginx"
```

## 10. 回滚

Java 回滚示例：

```powershell
ssh ubuntu@43.142.125.17 "sudo systemctl stop query-backend; sudo cp /var/backups/query/program-时间戳/geek-admin.jar /opt/query/geek-admin.jar; sudo chown queryapp:queryapp /opt/query/geek-admin.jar; sudo systemctl start query-backend"
```

管理端和免费查询页回滚时，将当前目录改名为 `.failed-时间戳`，再把对应备份目录移回原路径。数据库只在确认增量 SQL 无法修复时，使用对应时间点的备份恢复。

### 2.2 已实现的查询流程

1. 输入号码并检查格式，当前允许 5～20 位数字。
2. 获取安全验证令牌，携带访客标识和设备标识提交查询。
3. 获取查询结果，显示平台标记详情或未发现标记的提示。
4. 支持返回继续查询，并防止查询过程中重复提交。
5. 查询失败时展示错误提示，关闭等待状态。

首页目前展示泰迪熊、360、腾讯、百度、联通、移动高频、电话邦、搜狗、小米、114 的图标。图标列表是本地展示配置，实际查询的平台与结果以服务器配置和返回为准。

### 2.3 查询进度弹窗

- 从 `/h5/mark/policy` 读取 `result_delay_ms`；本次线上返回 `5000`，即 5 秒。
- 进度按后台等待时长推进，属于展示进度，并非逐个平台完成数量的实时统计。
- 尚未获取结果时，最高显示 99%；取得结果且满足等待时长后显示 100%。
- 100% 停留约 0.5 秒后显示结果；查询失败时直接结束等待并提示错误。
- 读取等待配置失败时，使用 6 秒作为备用时长。
- 已通过 9 个模拟场景：正常查询、慢查询、零等待时长、配置接口失败、查询被拒绝、无效号码与重复点击，以及网络等待、结果等待和 100% 停留期间退出页面。
- **这些是本地逻辑测试；新增弹窗的微信手机效果仍待确认。**

## 5. 给别人使用之前还需要做什么

按下面顺序推进：

1. **注册或切换正式小程序账号。**当前工程 AppID 属于“小程序测试号”，用于开发测试和真机预览。公众平台登录时应选择正式“小程序”；如只有测试号，则先注册正式小程序，并按实际主体与服务类目补齐资料。
2. **接入正式 AppID 并配置开发权限与域名。**正式账号准备好后替换工程 AppID，确认扫码登录的个人微信有开发权限，在正式账号后台重新配置 `https://biaoji.aleo1314.vip` 为 request 合法域名。已有代码与服务器可以继续复用。
3. **确定并配置客服方案。**如采用官方“小程序客服”，管理员应在正式账号后台的“客服消息”页面添加客服人员；代码再接入 `open-type="contact"` 按钮。当前尚未改动客服代码或绑定人员，不需要为此先注册公众号或接入企业微信。该客服会话不等同于添加用户为个人微信好友。
4. **重新编译并进行手机测试。**开启合法域名校验，确认新增进度弹窗、查询结果、较慢或失败时提示及最终选定的客服入口正常。
5. **部署第 4 节的查询适配服务兼容更新并回归。**在正式推广前完成。
6. **上传开发版本并创建体验版。**在开发者工具上传版本，在公众平台版本管理中设为体验版，按后台流程添加体验成员并提供体验码。体验版用于测试，不等于已向所有微信用户开放。
7. **核对微信后台上线资料。**检查名称、图标、介绍、服务类目、隐私保护指引及备案、认证等后台要求；目前这些项目的完成状态尚未逐项核实，按实际主体和微信后台要求补齐。
8. **提交审核，通过后发布。**目前无已提交审核、审核通过或发布成功记录。

## 6. 后续下线旧免费查询网页时的边界

计划是用小程序承接原免费查询入口，但小程序目前继续复用原系统的查询接口。

| 内容 | 迁移时的处理方式 |
| --- | --- |
| 原网页入口 `/query/` | 等小程序发布并验证后，再决定关闭、提示迁移或保留 |
| `/h5/security/challenge` | 小程序仍在使用，必须保留 |
| `/h5/mark/policy` | 小程序进度弹窗仍在使用，必须保留 |
| `/h5/mark/query`、`/h5/mark/getInfo` | 小程序查询与结果获取仍在使用，必须保留 |
| `query-free` 服务 | 当前同时承载网页和 API；不能因为下线网页而直接停掉整个服务 |
| Java 查询后端、数据库及相关平台配置 | 继续保留，支撑小程序查询 |
| `biaoji.aleo1314.vip` 的 DNS、证书和 Nginx `/h5/*` 转发 | 继续保留；变更 API 域名时需同步小程序配置和微信合法域名 |

本轮没有关闭旧网页，也没有变更生产路由。

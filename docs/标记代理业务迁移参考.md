## 1.1 本次确认范围

本次只迁移以下内容：

- 用户端 9 个业务平台的提交、预查询、订单和结果页面。
- 代理端 9 个业务平台的订单处理、成功/失败回填、退款和额度流水。
- 支撑上述流程所必需的订单、订单明细、平台额度、钱包流水和用户关联接口。
- 代理账户能看到自己的下游订单和处理页面。

明确不迁移：

- 标记业务管理员后台
- 治理规则
- 仲裁工单
- 审计看板
- 独立模板管理页面
- 与本次业务无关的免费查询、手机端和其他平台管理功能

这里的“9 个平台”按业务品牌计算：泰迪熊、腾讯、360、百度、搜狗、移动高频、电话邦、联通管家、小米手机。泰迪和 360 的内部流程编码仍需保留，因此数据库中仍会出现 13 个处理代码。

## 2. 业务链路

```text
标记用户提交号码
    -> 创建 mark_order / mark_order_item
    -> 按平台扣减额度并写钱包流水
    -> 自动关联代理并进入待处理状态
    -> 代理处理订单或平台自动处理
    -> 成功完成 / 失败退款
    -> 更新订单统计、通知和处理记录
```

代理端依赖以下业务对象：订单、订单明细、平台单价、平台额度、钱包流水、下游账户关系和角色权限。为兼容来源订单模型可保留 `audit_status` 字段，但新订单直接写为通过状态，不提供审核页面。

## 3. 13 个平台处理方式

13 个菜单入口不等于 13 套完全独立的代码，实际分为特殊流程和通用人工流程。

| 平台代码 | 页面名称 | 代理处理方式 | 关键逻辑 |
| --- | --- | --- | --- |
| `tengxun` | 腾讯 | 自动处理 | 用户提交验证码后约 30 秒后台调用腾讯接口，自动成功或失败，失败自动退款 |
| `td_gaopin` | 泰迪高频 | 定时自动检测 | 后台每 30 秒复查，符合条件后自动完成，未完成时代理不能手动修改 |
| `td_second` | 泰迪二次 | 提交即完成 | 用户发送短信验证码并调用 TDX 接口，成功后直接生成完成订单 |
| `xiaomi` | 小米手机 | 半自动 | 代理先批量开启处理，进入状态 `3`，之后查询号码是否已无标记 |
| `yidonggaopin` | 移动高频 | 人工处理 | 下单前有专门的有标记校验，代理端使用通用人工工作台 |
| `taidixiong` | 泰迪熊 | 人工处理 | 通用人工工作台 |
| `sanliuling` | 360 | 人工处理 | 独立平台编码，处理逻辑通用 |
| `qihu_first` | 360首次 | 人工处理 | 独立平台编码，处理逻辑通用 |
| `qihu_second` | 360二次 | 人工处理 | 独立平台编码，处理逻辑通用 |
| `baidu` | 百度 | 人工处理 | 用户端有专用页面，代理端使用通用工作台 |
| `sghmt` | 搜狗 | 人工处理 | 通用人工工作台 |
| `dianhuabang` | 电话邦 | 人工处理 | 通用人工工作台 |
| `ltgj` | 联通管家 | 人工处理 | 通用人工工作台 |

通用人工流程支持单条成功/失败、失败退款、失败改成功重新扣费、整单处理、批量处理和导出。

## 8. 已发现的迁移风险

### 8.1 小米自动复查链路不完整

来源代码已有 `processXiaomiPendingItemsAuto()`，但当前没有定时任务调用它。前端还定义了 `/autoDetectXiaomi` 和 `/batchDetectXiaomi`，后端没有对应 Controller 映射。

迁移时必须补齐以下之一：

1. 增加可靠的定时任务，周期性处理 `xiaomi` 的状态 `3` 明细；或
2. 增加明确的手动复查接口，并在前端提供可见操作。

### 8.2 腾讯不能使用通用人工接口

腾讯订单由后台自动提交，代理回填接口会拒绝腾讯订单。必须同时迁移腾讯专用调用链和异步任务。

### 8.3 泰迪高频状态语义不同

`td_gaopin` 的状态 `3` 在部分场景表示“待自动检测”，不能简单按照其他平台的“处理中”展示和筛选。

### 8.4 平台代码不能合并

以下代码虽然属于同一品牌或相近流程，但必须保留独立编码：

```text
taidixiong / td_gaopin / td_second
sanliuling / qihu_first / qihu_second
```

否则会影响模板、额度、历史订单和菜单筛选。

### 8.5 当前项目已有免费查询安全改动

合并时不得覆盖当前项目的：

- 免费查询内部密钥校验
- 动态签名令牌
- IP、设备和指纹限流
- CORS 和内部接口限制
- Python 免费查询代理配置

6. 编译后端并测试订单、审核、处理、退款和额度流水。

## 13. 正式库执行顺序

1. 备份正式数据库和当前部署包。
2. 在测试库先执行 `backend/sql/mark_business_minimal.sql`。
3. 给现有账号绑定角色，不需要重新创建 `admin`。
4. 给用户账号初始化 13 个内部平台编码的余量。
5. 部署后端和前端构建产物。
6. 分别使用管理员、代理、用户账号验收菜单和订单链路。

角色绑定示例：

```sql
SET @agent_user_id := 代理账号的sys_user.user_id;
SET @mark_user_id := 用户账号的sys_user.user_id;

INSERT IGNORE INTO sys_user_role (user_id, role_id)
SELECT @agent_user_id, role_id FROM sys_role WHERE role_key = 'mark_agent';

INSERT IGNORE INTO sys_user_role (user_id, role_id)
SELECT @mark_user_id, role_id FROM sys_role WHERE role_key = 'mark_user';
```

用户余量初始化示例。`@initial_quota` 必须按实际业务填写，脚本不默认赠送次数：

```sql
SET @mark_user_id := 用户账号的sys_user.user_id;
SET @initial_quota := 实际初始次数;

INSERT INTO mark_user_platform_quota
  (user_id, platform_code, platform_name, remain_count, create_by, create_time)
SELECT @mark_user_id, p.platform_code, p.platform_name, @initial_quota, 'admin', NOW()
FROM (
  SELECT 'taidixiong' platform_code, '泰迪熊' platform_name
  UNION ALL SELECT 'td_gaopin', '泰迪高频'
  UNION ALL SELECT 'td_second', '泰迪二次'
  UNION ALL SELECT 'tengxun', '腾讯'
  UNION ALL SELECT 'sanliuling', '360'
  UNION ALL SELECT 'qihu_first', '360首次'
  UNION ALL SELECT 'qihu_second', '360二次'
  UNION ALL SELECT 'baidu', '百度'
  UNION ALL SELECT 'sghmt', '搜狗'
  UNION ALL SELECT 'yidonggaopin', '移动高频'
  UNION ALL SELECT 'dianhuabang', '电话邦'
  UNION ALL SELECT 'ltgj', '联通管家'
  UNION ALL SELECT 'xiaomi', '小米手机'
) p
ON DUPLICATE KEY UPDATE
  platform_name = VALUES(platform_name),
  remain_count = VALUES(remain_count),
  update_by = 'admin',
  update_time = NOW();
```

代理应创建用户账号，或保证该用户的 `sys_user.create_by` 是代理登录名。这样订单会自动分配给对应代理，其他代理无法读取。

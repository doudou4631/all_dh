# 标记无码平台接入说明

本次按现有侧栏增加三个并列平台入口。用户端复用一个独立的无码提交页，代理端复用现有处理工作台；订单可由巡检策略自动接管，代理仍可在工作台人工介入。

| 显示名称 | 平台编码 | 处理方式 |
| --- | --- | --- |
| Taidixiong无码 | `wuma_taidixiong` | 自动巡检，可由代理人工介入 |
| Tengxun无码 | `wuma_tengxun` | 自动巡检，可由代理人工介入 |
| 360无码 | `wuma_360` | 自动巡检，可由代理人工介入 |

用户可批量粘贴手机或固话号码，提取、去重后点击“批量提交”。网页先逐号检测并展示标记状态，所有号码均有标记时才能确认提交；后端创建订单前再次强制检测，存在无标记、不符合条件或检测失败号码时整批拒绝，不创建订单、不扣处理次数。下单按本平台单价扣除次数，自动审核后进入代理队列。任务记录支持搜索、筛选、备注、复制、导出和查看处理结果。

三个平台使用各自的订单编码、余额和流水，不需要验证码或上游处理提交。巡检策略可设置执行间隔、单次上限、订单范围（待处理、处理中或两者）和无标记时的处理结果；无码策略接管待处理订单时无需代理点击“开始处理”。巡检检测到无标记后，按策略标记成功或失败；失败会退回对应平台次数，重复处理不会重复退款。默认同时检测两种状态时，仍有标记或查询失败的明细转为或保持处理中并等待下一轮；若范围设为“仅待处理”，则保留待处理状态以便下一轮继续扫描。代理仍可在工作台逐条或批量调整状态；已退款号码改为成功时重新扣次，次数不足时拒绝改为成功。

默认的三个无码巡检策略使用“待处理和处理中”范围并启用“自动接管待处理”。管理员可在“自动巡检 → 巡检策略”调整间隔、单次上限、无标记后的处理结果和运行开关。若希望保留代理手动开始处理的流程，将范围设为“仅处理中”并关闭自动接管；无码策略选择包含待处理的范围时，必须启用自动接管。泰迪高频平台仍使用专用待处理规则，不受此设置影响。

## 生效步骤

1. 在已安装现有标记业务表和平台管理表的业务数据库中，执行 `backend/sql/mark_wuma_manual_processing.sql`；检测配置执行可重复运行的 `backend/sql/mark_wuma_query_api_config.sql`，确认三个同编码的检测接口启用、聚合配置有效。正式服务器已执行这两个脚本。
2. 部署网页预检测功能后，执行数据库增量脚本 `backend/sql/mark_inspection_order_scope.sql`，再部署包含自动接管功能的后端与前端。该增量脚本仅补充巡检范围和统计字段，并初始化尚未设置这些值的策略；不要用 `backend/sql/mark_auto_inspection.sql` 替代，它是初始化脚本并会停用巡检策略。
3. 在“平台管理”确认三个平台的来源、目标、映射开关均开启，保持三个平台各自一对一映射。
4. 在“自动巡检 → 巡检策略”确认三个无码策略已启用，订单范围为“待处理和处理中”，且“自动接管待处理”已开启；按需调整执行间隔、单次上限和无标记后的处理结果。
5. 在需要开通的用户所绑定的标记模板中，添加以上三个平台并配置每号码消耗次数。已有模板不会被脚本自动追加或覆盖。
6. 通过现有代理管理充值流程，分别为需要使用的平台充值次数。
7. 退出后重新登录，更新菜单和权限。代理端的三个入口直接位于原有“标记处理”下面，与现有平台并列；用户端也有三个独立入口。

脚本为系统现有的管理员、用户、代理及子代理角色绑定对应菜单和操作权限；自定义角色需在角色管理中勾选这些菜单及所需操作权限。菜单显示还受平台总开关控制；用户是否能够提交取决于模板配置和平台剩余次数。

脚本可重复执行，不重复创建相同路径的菜单或平台映射，保留已有平台开关及余额；会同步这三个平台的显示名称和排序。菜单 ID 使用系统自增值。

## 验收

1. 在任意一个无码平台输入两个有标记号码，确认展示逐号检测结果，勾选确认后才能提交；只扣该平台的次数，重复号码只生成一条明细。对无标记、检测失败及混合批次，确认整批不创建订单、不扣次数；直接调用创建订单接口同样受限。
2. 在同名代理平台查看订单，确认普通平台和另外两个无码平台的队列不含该订单。
3. 以启用“自动接管待处理”的策略执行巡检，确认待处理无码订单无需代理操作即可被扫描。
4. 巡检检测到无标记时，确认按策略自动标记成功或失败；检测仍有标记或查询失败时，确认明细保持处理中并由后续巡检重试。
5. 将一个号码标为失败，核对用户余额和退款流水；再次标为失败不增加余额。
6. 将已退款号码标回成功，或先改待处理再改成功，确认重新扣回对应次数。
7. 在用户任务记录中查看状态、结果和处理时间。
8. 关闭平台映射后重新登录，确认菜单隐藏且不能继续下单。

客户 API 和网页共用后端校验，每次创建订单只执行一轮检测；已成功订单按相同 `requestNo` 重试直接返回原订单，不重复检测或扣次。三个无码平台只按自己的接口编码选择配置，配置缺失或停用时拒绝提交。

本地验证覆盖三个平台的标记检测、整批拦截、平台余额隔离、幂等重试、退款与重新扣次、代理人工处理及自动接管巡检，以及现有代理备注和客户 API 凭据。网页测试覆盖确认前不下单、检测失败、缺失/重复/错号结果、重复点击、编辑和切平台后的旧结果失效，以及网络异常后原请求重试。巡检策略自动接管已于 2026-10-27 03:07:04（Asia/Shanghai）正式上线，网页与客户 API 订单共用巡检规则；发布验证和回滚路径见《正式服务器部署与更新说明》第 18 节。

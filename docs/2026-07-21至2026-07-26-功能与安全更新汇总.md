## 一、2026-07-21 免费查询功能与安全更新

### 1. 更新概述

本次更新围绕独立免费查询前端、后台管理功能、查询统计、IP 访问策略和接口安全进行完善。

当前服务结构：

```text
管理端 Vue（80）
        |
        v
Java 后端（127.0.0.1:8080）
        ^
        |
Python 免费查询代理（127.0.0.1:18765）
        ^
        |
免费查询浏览器页面
```

Java 后端和 Python 免费查询代理均只监听本机地址，不能从局域网直接访问其内部端口。

### 7. IP 访问策略

后台支持配置：

- 结果显示延时，当前配置为 6000ms。

- 白名单 IP。

结果显示延时的含义：从提交查询开始，到返回结果的总时间至少达到配置值。查询接口本身超过配置值时，不再额外等待。

### 8. 动态签名令牌

每次免费查询前，浏览器会自动获取一次性安全令牌。

令牌规则：

- 使用 HMAC-SHA256 进行服务端签名。
- 默认有效期为 90 秒。
- 90 秒只是提交有效期，不是查询等待时间。
- 每个令牌只能使用一次。
- 重复提交同一令牌会被拒绝。
- 令牌绑定真实 IP、设备 Cookie、浏览器指纹和 User-Agent。
- 篡改、过期、环境不一致或缺少令牌时拒绝查询。
- 令牌签名密钥不会发送到浏览器。

安全挑战接口：

```text
POST /h5/security/challenge
```

Java 内部接口：

```text
POST /server/freeQuery/challenge
POST /server/freeQuery/single
```

Java 内部接口必须携带 Python 代理使用的内部服务密钥，浏览器不能直接调用。

### 9. 多维度指纹限流

浏览器指纹摘要包含：

- User-Agent
- 操作系统和浏览器平台
- 语言
- 时区
- 屏幕尺寸和颜色深度
- CPU 核数
- 设备内存
- 触控点数量
- Canvas 摘要
- WebGL 厂商和渲染器摘要

浏览器仅发送 SHA-256 摘要，后端不保存上述原始指纹字段。

当前限流规则：

| 维度 | 限制 |
| --- | --- |
| 精确 IP | 跟随后台每日查询限额 |
| 设备 Cookie | 跟随后台每日查询限额 |
| 浏览器指纹 | 跟随后台每日查询限额 |
| IPv4 `/24` 或 IPv6 `/56` 网段 | 每日最少 100 次，或 IP 限额的 5 倍 |
| 同一查询号码 | 每小时 5 次 |
| 挑战令牌领取 | 每 IP、设备或指纹 10 分钟 30 次 |
| 网段挑战令牌领取 | 10 分钟 120 次 |
| 全站查询并发 | 默认 8 个 |

当前令牌消费和多维限流状态使用单 Java 实例内存保存。部署多个 Java 后端实例时，必须迁移到共享 Redis。

### 10. 接口安全加固

已完成以下安全修复：

- Java 后端 8080 仅监听 `127.0.0.1`。
- Python 免费查询服务 18765 仅监听 `127.0.0.1`。
- Java 查询接口要求内部服务密钥。
- 不再信任浏览器提交的 `X-Forwarded-For`。
- Python 代理仅接受本机反向代理覆盖写入的 `X-Real-IP`。
- 后端只接受 Python 代理传递的 `X-Free-Query-Client-IP`。
- 免费查询接口拒绝跨站 Origin 请求。
- 后端 CORS 仅允许配置的管理端来源。
- 匿名用户不能读取平台 API 配置。
- 平台 URL、请求头模板和前置操作配置不再匿名泄露。
- Python 服务请求体限制为 16KB。
- 禁止通过静态服务下载 `server.py`、环境配置和启动脚本。
- 浏览器可见 HTML、JS、CSS 和图片资源中不包含内部服务密钥。

当前允许的本地管理端来源：

- `http://localhost`
- `http://127.0.0.1`
- `http://192.168.5.83`
- 上述地址的其他端口形式

其他来源默认返回 403。

### 11. 后台登录修复

登录验证码校验已改为跟随系统配置：

- `sys.account.captchaEnabled=false`：不显示、不校验验证码。
- `sys.account.captchaEnabled=true`：显示并校验验证码。

当前配置为关闭验证码，账号密码登录已经验证成功。

### 12. 环境变量

生产环境必须配置以下变量：

```text
FREE_QUERY_INTERNAL_KEY=长度足够的随机代理密钥
FREE_QUERY_SIGNING_KEY=另一条不同的随机签名密钥
CORS_ALLOWED_ORIGIN_PATTERNS=实际管理端域名
FREE_QUERY_MAX_CONCURRENT=8
FREE_QUERY_TOKEN_TTL_SECONDS=90
```

要求：

- Java 后端与 Python 代理的 `FREE_QUERY_INTERNAL_KEY` 必须相同。
- `FREE_QUERY_SIGNING_KEY` 只供 Java 后端签发动态令牌使用。
- 两个密钥不能相同。
- 生产环境不能使用项目内的开发默认值。
- 密钥不能写入浏览器代码、公开文档或日志。

### 13. 反向代理要求

正式上线时：

- 不得直接暴露 Java 后端 8080 端口。
- 不得直接暴露 Python 服务 18765 端口。
- 只通过正式域名的反向代理发布管理端和免费查询页面。
- 免费查询代理必须覆盖写入 `X-Real-IP`。
- 不得透传客户端自行提交的 `X-Real-IP` 或 `X-Forwarded-For`。
- 管理端正式域名必须加入 `CORS_ALLOWED_ORIGIN_PATTERNS`。

## 四、2026-07-26 代理管理、次数充值与权限调整

### 1. 代理管理模式

- 代理管理调整为“上级代理 -> 下级代理 -> 普通账户”的管理方式。
- 下级代理只能查看和管理自己创建的直属下级账户，不能查看其他代理账户。
- 下级代理创建的业务账户默认绑定 `mark_user` 角色，账户菜单和接口权限以绑定角色为准。
- 普通账户不再继承代理管理菜单及代理操作按钮权限。
- 创建账号、修改状态、重置密码、次数充值均增加直属上下级关系校验。
- 修复下级代理列表不显示当前账户所创建下级账户的问题。
- 修复部分代理账户虽然已绑定角色和菜单，接口仍提示“没有权限，请联系管理员授权”的问题。

### 2. 平台次数充值

- 余额模式调整为按平台分别记录可用次数，不再使用一个通用积分余额代替全部平台次数。
- 管理员可以按指定平台给代理账户充值次数。
- 上级代理给直属下级充值时，从上级同一平台的剩余次数中扣除，并给下级同平台增加次数。
- 不允许跨平台划转。例如上级 Taidixiong二次有 100 次、小米有 0 次时，只能划转 Taidixiong二次次数。
- 上级对应平台次数不足时禁止充值，并提示当前平台剩余次数不足。
- 充值次数必须为正数；同一请求号禁止重复处理。
- 增加平台次数充值交易记录和账户平台次数流水，记录转出账户、转入账户、平台、变动前后次数及操作人。

### 3. 角色和菜单权限

- 账户实际可用菜单及接口权限统一由账户绑定角色决定。
- `mark_user` 角色拥有其后台勾选的用户端业务菜单权限。
- 普通账户固定使用 `mark_user` 角色，不再要求额外绑定标记代理角色。
- 代理角色保留代理新增、状态修改、密码初始化和次数充值等代理管理权限。
- 修复角色已勾选菜单，但页面请求仍被后端权限注解拦截的问题。
- “号码查询 -> 单次查询”和“批量查询”分别绑定独立权限字符：
  - `server:apiServer:singleQuery`
  - `server:apiServer:batchQuery`

### 4. 号码查询

- 可查询平台列表同时按账户角色权限过滤，避免出现菜单可见但接口提示无可用 API 平台的情况。

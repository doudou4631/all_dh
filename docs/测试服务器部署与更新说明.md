## 2. 部署结构

```text
公网浏览器
    |
    v
Nginx :80
    |-- /              -> 管理端静态文件 /var/www/query/admin
    |-- /free-query/   -> Python 免费查询服务 127.0.0.1:18765
    `-- /prod-api/     -> Java 后端 127.0.0.1:8080

Java 后端 -> MariaDB 127.0.0.1:3306 / verifynum
```

服务器主要目录：

| 路径 | 说明 |
| --- | --- |
| `/opt/query/geek-admin.jar` | Java 后端程序 |
| `/opt/query/free-query` | 免费查询页及 Python 服务 |
| `/var/www/query/admin` | 管理端构建产物 |
| `/var/lib/query/uploads` | 后端上传文件 |

| `/var/log/query` | Java 应用日志 |

| `/etc/systemd/system/query-free.service` | Python systemd 服务 |

`/etc/query/query.env` 包含敏感信息，不能下载到项目、提交到 Git 或发送给他人。

## 3. 更新前检查

在本机项目根目录执行：

```powershell
ssh ubuntu@212.64.16.212 "systemctl is-active query-backend query-free nginx mariadb"
```

四行都应显示 `active`。更新前必须备份数据库：

```powershell
ssh ubuntu@212.64.16.212 "sudo mkdir -p /var/backups/query; sudo mariadb-dump --single-transaction --routines --triggers verifynum | gzip | sudo tee /var/backups/query/verifynum-before-update.sql.gz > /dev/null"
```

如果是重要更新，另外备份当前程序：

```powershell
ssh ubuntu@212.64.16.212 "sudo rm -rf /opt/query/backup /var/www/query/admin.backup; sudo mkdir -p /opt/query/backup; sudo cp /opt/query/geek-admin.jar /opt/query/backup/; sudo cp -a /opt/query/free-query /opt/query/backup/; sudo cp -a /var/www/query/admin /var/www/query/admin.backup"
```

本机重新构建：


## 7. 数据库变更

日常更新禁止重新导入 `backend/sql/verifynum.sql`，该文件包含 `DROP TABLE` 和初始化数据，会覆盖现有测试数据。

新增表或字段时，应编写独立的增量 SQL，并遵循以下流程：

1. 先执行数据库备份。
2. 检查 SQL 是否只包含本次所需变更。
3. 将增量 SQL 上传到 `/tmp`。
4. 执行 SQL 后检查表结构和关键数据。
5. 最后更新并重启 Java 后端。

执行增量 SQL 示例：

```powershell
scp backend\sql\本次增量.sql ubuntu@212.64.16.212:/tmp/update.sql
ssh ubuntu@212.64.16.212 "sudo mariadb verifynum < /tmp/update.sql && rm -f /tmp/update.sql"
```

## 11. 安全注意事项

- 当前是测试服务器，仍应避免使用真实用户敏感数据。
- 当前只配置 HTTP；绑定正式域名后应配置 HTTPS。
- 不要开放 Java `8080`、Python `18765` 或 MariaDB `3306` 到公网。
- 不要把 `/etc/query/query.env` 中的内容写入代码或文档。
- 更新 Nginx 配置后先执行 `sudo nginx -t`，通过后再重载。
- 不要直接执行来源不明的 SQL、Shell 脚本或依赖升级命令。
- `npm audit` 当前存在依赖风险项，升级依赖前应先在本地完成构建和功能回归。

```bash
TDX_SECOND_QMF_USERNAME=实际账号
TDX_SECOND_QMF_PASSWORD=实际密码
TDX_SECOND_QMF_APP_ID=78811
TDX_SECOND_QMF_QR_CODE=1
TDX_SECOND_ORIGINAL_IP=127.0.0.1
TDX_SECOND_TIMEOUT_MS=120000
```

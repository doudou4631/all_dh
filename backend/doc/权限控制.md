### 与权限有关的注解

`@Anonymous`注解用于配置公开接口

`@PreAuthorize`注解用于配置接口要求用户拥有某些权限才可访问，它拥有如下方法

| 方法        | 参数   | 描述                                           |
| ----------- | ------ | ---------------------------------------------- |
| hasPermi    | String | 验证用户是否具备某权限                         |
| lacksPermi  | String | 验证用户是否不具备某权限，与 hasPermi逻辑相反  |
| hasAnyPermi | String | 验证用户是否具有以下任意一个权限               |
| hasRole     | String | 判断用户是否拥有某个角色                       |
| lacksRole   | String | 验证用户是否不具备某角色，与 isRole逻辑相反    |
| hasAnyRoles | String | 验证用户是否具有以下任意一个角色，多个逗号分隔 |

注意：本项目 `hasRole/hasAnyRoles` 语义对 `admin` 含放行逻辑（超级管理员视为拥有任意角色）。该语义适用于权限放行，不适用于业务链路身份分支判断（例如“是否代理操作者”）。

```java
@PreAuthorize("@ss.hasPermi('system:user:list')")
@PreAuthorize("@ss.lacksPermi('system:user:list')")
@PreAuthorize("@ss.hasAnyPermi('system:user:add,system:user:edit')")
```

`@DataScope`注解用于配置接口数据权限

* `deptAlias`用于指定部门表的别名;
* `userAlias`用于指定用户表的别名;
* 实体需要继承BaseEntity类;
* `全部数据权限`、`自定数据权限`、`部门数据权限`、`部门及以下数据权限`、`仅本人数据权限`五种权限模式在后台角色管理界面配置数据权限

```java
// 部门数据权限注解
@DataScope(deptAlias = "d")
// 部门及用户权限注解
@DataScope(deptAlias = "d", userAlias = "u")
```

1. 使用注解

```java

@DataScope(deptAlias = "d", userAlias = "u")
public List<...> select(...)
{
    return mapper.select(...);
}
```

2. 配置mybatis的xml

```xml
<select id="select" parameterType="..." resultMap="...Result">
    <include refid="select...Vo"/>
    <!-- 数据范围过滤 -->
    ${params.dataScope}
</select>
```

### 标记业务角色矩阵（主文档，2026-06 更新）
本章节为标记业务角色规则的单一维护入口。

#### 1) 适用范围
本文档描述当前已落地的“标记业务权限收敛”规则（阶段 C + D），用于开发、测试、发布验收统一口径。

#### 2) 当前角色键与含义
- `admin`：平台超级管理员（全量权限账号；当前已从菜单绑定层面移除“标记业务管理”入口）。
- `mark_admin`：标记业务管理员（独立产品管理员角色）。
- `agent` / `mark_agent`：标记代理（兼容并存角色键）。
- `user` / `mark_user`：标记下游用户（兼容并存角色键）。
- `common`：通用角色，不属于标记链路可分配目标。
说明：`mark_admin` 已启用，作为“标记业务管理”模块的专用管理角色。

#### 3) 权限边界原则
- 后端接口是最终权限边界；前端收敛仅用于降低误操作。
- 代理链路角色分配必须经过后端白名单校验，不能依赖前端选项限制。
- 菜单展示以 `getRouters` 返回为准，本质取决于 `sys_role_menu` 绑定而非账号名称。

#### 4) 数据范围（代理视角）
- 非超管且命中 `agent/mark_agent` 时，用户查询仅允许看到：
  - 本人账号；
  - 由本人创建链路中的账号。

#### 5) 角色可见集合（读接口）
`GET /system/user/`、`GET /system/user/{userId}` 返回的 `roles` 会按操作者身份与目标用户收敛：

- 超级管理员：可见全部角色
- 代理操作者（`agent/mark_agent`）：
  - 编辑本人：仅可见 `agent/mark_agent`
  - 编辑下游：仅可见 `user/mark_user`
- 其他非超管：过滤掉管理员角色

`GET /system/user/authRole/{userId}` 的角色回显也执行同样收敛逻辑。

#### 6) 角色写入白名单（写接口）
以下接口统一执行“可分配角色白名单”校验：

- `POST /system/user`
- `PUT /system/user`
- `PUT /system/user/authRole`

对代理操作者的约束：

- 目标为本人：仅允许分配 `agent/mark_agent`
- 目标为下游用户：仅允许分配 `user/mark_user`
- 任何其他角色（如 `admin`、`common`）都会被拒绝

#### 7) 角色分配矩阵（当前生效）
`admin`：
- 可按现有平台权限模型管理角色与用户，不受本矩阵限制。
- 当前为实现“标记业务模块独立登录入口”，已在菜单绑定层解绑“标记业务管理”菜单组。

`mark_admin`：
- 用于承载“标记业务管理”模块管理员能力。
- 建议仅绑定模块内管理菜单，不承担平台全局系统管理职责。
- 独占标记模板管理权限（`server:markTemplate:add/edit/remove`），并可在“代理账户”页执行“绑定模板”。

`agent` / `mark_agent`：
- 编辑本人账号：仅允许分配 `agent`、`mark_agent`。
- 编辑下游账号：仅允许分配 `user`、`mark_user`。
- 禁止分配：`admin`、`common` 及其他非标记下游角色。
- 不再拥有“标记模板”菜单及新增/修改/删除能力，仅消费已绑定模板。

`user` / `mark_user` / `common`：
- 不应承担标记链路中的角色分配管理职责（除非被额外授予系统管理权限）。

标记业务管理模块菜单绑定（当前线上）：
- `mark_admin`（`role_id=5`）绑定：
  - `900100000001` 标记业务管理
  - `900100000108` 代理账户
  - `900100000105` 治理规则
  - `900100000106` 仲裁工单
  - `900100000107` 审计看板
  - `900100000127` 标记模板
- `mark_admin` 同时绑定模板功能点：`900100001701`（query）、`900100001702`（add）、`900100001703`（edit）、`900100001704`（remove）。
- `admin`（`role_id=1`）当前已解绑以上菜单组。
- `agent/mark_agent` 当前已解绑 `900100000127` 与 `900100001701-900100001704`。
- 默认模块管理员账号：`userName`（初始密码 `123456`，首次登录后应立即修改）。

#### 8) 前端实现注意（代理链路）
- 代理身份判断必须对 `agent/mark_agent` 做精确匹配（例如基于当前用户角色集合直接判断）。
- 不应直接复用带 `admin` 放行语义的通用角色判断，否则会把超级管理员误判为代理，进而触发错误的角色下拉收敛。
- 代理账户页新增下游角色默认值应仅从 `user/mark_user` 选择，不再使用 `common` 作为默认候选。

#### 9) 数据范围与模板继承规则
- `agent/mark_agent` 查询用户列表时，仅可见本人及其创建链路内账号。
- 代理在代理账户链路新增/修改下游账号时，下游账号 `rel_mark_template` 由后端强制继承“处理账号（agent/mark_agent）已绑定模板”。
- 若处理账号未绑定模板，则下游账号写入会被拒绝（需先给处理账号绑定模板）。
- 已存在下游账号在后续写入时同样会按处理账号模板对齐，避免链路模板漂移。

#### 10) 验收检查点
- 代理通过新增/编辑/授权角色接口无法分配 `common`、`admin`。
- 代理调用角色回显接口时，看不到越权角色。
- 代理用户列表仅包含本人与本人创建链路账号。
- 前端代理账户页不再出现 `common` 作为默认候选。
- `mark_admin` 可新增/修改/删除标记模板；`agent/mark_agent` 不可见模板菜单且调用模板写接口返回无权限。
- 代理侧创建/修改下游账号时，后端落库模板与处理账号 `rel_mark_template` 一致；处理账号无模板时写入失败。
- `userName` 登录后可看到“标记业务管理”菜单组。
- `admin` 登录后不再看到“标记业务管理”菜单组（除非重新回绑 `role_id=1` 菜单）。
